# Epic 13: the web UI

## What the pattern was

**A generic UI over declared runs.** The browser never chooses what runs. A pack ships a view
file, and the view file declares screens and actions. Each is a pack plus a map from the pack's
vars to one of five closed binding sources: `param`, `input`, `state`, `const`, `server`. The
browser sends ids and declared values; the server resolves the rest from the file it loaded at
boot. That turns the registry's most dangerous tools (`file.read`, `http.request`) into
something the browser cannot name. The security rule is a data-shape rule: there is no field in
`RunRequest` that could carry a pack path, so there is nothing to validate it against.

**The second surface through Epic 12's seam.** Every screen is `Runner.Run` on a per-run
`WithProgress` copy of the shared runner, and reads go through generic tools (`index.find`,
`docs.get`, `judge.assess`) rather than through a second path to the store. The adapter owns
transport, sessions, rendering and the consent gate; it owns no business rule. `git diff
--stat -- internal/core` across the epic is empty.

**Composition root as the only place that knows where data goes.** `web` cannot import config,
the provider or `packfile`. So `cmd/atlas` hands it plain values and functions: the pack loader
as `func(path) (Blueprint, error)` (P2), the egress table built from what `buildRegistry`
actually constructed over the model clients, and a `ports.Permission` implementation (`Asker`)
to use as the agent's human. Everything the browser learns about egress comes from that table,
and the table is pinned against the registry by `TestEgressTableCoversModelTools`.

**Bridging a blocking port to a stream.** `ports.Permission.Decide` blocks and returns a
decision. The web asker makes that an `Ask` message on the stream of the run holding the slot,
and waits for `Answer`, the stream closing, the run ending, or a timeout. Every path but an
explicit allow denies. Epic 12's rule for unattended use (an ask with nobody to answer denies,
never hangs) held without a special case.

**One run slot.** `gitdocs` is unlocked, so the server has a one-token channel. Every run,
including the server's own internal reads, takes it. Epic 12's lock serialises processes; the
slot serialises runs inside the one process.

## The rulings that mattered

From the plan:

- **P1, one shared runner.** Epic 12 had already made `WithProgress` return a copy, so the
  spec's "fresh runner per run" was one line.
- **P4, the gate is per server (spec amendment).** The spec gated a run whose blueprint named a
  hosted tool. Epic 10's `pack.each` runs child packs whose steps the parent does not name, so a
  blueprint walk would miss them. While any hosted endpoint is unacknowledged, every `Run`
  refuses. The cost is one consent click before a run that would never have reached the model;
  the benefit is that the gate cannot leak through nesting.
- **P5, hosted means not `localhost` and not a loopback literal.** No DNS lookup, so a LAN
  engine behind a hostname asks once.
- **P6, an acknowledgement is a record document read back with `index.find`.** `ports.Docs` has
  no not-found error to branch on; an index row answers "is there one".
- **P7, files under one root (spec amendment).** The spec's `Document` served record paths only,
  but Epics 9 and 10 write PDFs to disk. `Web.FilesRoot` plus `os.Root` serves them as
  downloads, and `os.Root` refuses `..`, absolute paths and escaping symlinks without any path
  logic of ours. The `file` widget is the browser side.
- **P8, `state` is a server-side cache.** An action's `state.` binding reads the screen's last
  result from memory keyed by view, screen and params, so the browser cannot forge it.

Made while building:

- **Connect code lives in `uiv1` itself.** The generator's default `uiv1connect` subpackage
  imports its parent, which `TestInboundAdaptersStayIsolated` forbids. `protoc-gen-connect-go`'s
  `package_suffix` option with an empty value removes the ancestor edge at the source, and the
  architecture rule stayed as it was (`9e91190`, plan `286d2c6`).
- **`Queued.ahead` counts runs waiting for or holding the slot, released on slot release.**
  The brief said to decrement on take, which contradicted its own test. With this rule, ahead
  means "runs in front of you".
- **Consent state is read once and held in memory.** The first need reads every hosted
  endpoint's acknowledgements; afterwards the gate and `Views` answer from memory, and
  `Acknowledge` updates it. The store lock means nothing else writes `atlas/egress/` while the
  server runs, and a gate check queued behind a ten-minute run would have stalled every page
  load (`252e3bb`, pinned by `TestGateAnswersWithoutTheRunSlot`).
- **Nil slices are fixed at the Go source.** A YAML view that omits a list decoded to nil and
  reached the browser as JSON `null`. `LoadViews` normalises every slice, pinned by a test that
  marshals the fixture and finds no null, so no widget needs a null guard (`d475b5d`).
- **Ctrl-C cancels runs.** `http.Server`'s default base context is not cancelled by `Shutdown`,
  so a streaming run held shutdown for the whole budget and exited non-zero. `BaseContext`
  returning the signal context ends open runs and asks (which deny), and serve returns nil
  (`1f1b053`, `TestServeStopsWithARunInFlight`).
- **`index.find` returns rows newest first.** `sqlindex.Find` has no ORDER BY, so `limit: 1`
  meant "some row", and a subject judged twice could show, and Approve could bind, an older
  judgement. Sorting after a limited query cannot fix that, so the tool now reads without a
  limit, sorts by `When` descending and then truncates (`daf4ca3`). A port and both index
  adapters are unchanged.
- **`judge.assess`.** The review screen must show reasons, and Epic 7 requires thin coverage to
  be visible in them. Reasons are computed by `app.Assess`, never stored. A generic tool re-runs
  `ReadJudgement` plus `Assess` on a recorded judgement, the same pair `judge.each` runs for a
  cached one (`a79a09e`).
- **Table columns are dotted paths.** Columns like `fields.subject_id` rendered empty because the
  table read `row[col]`; it now uses the same lookup as every other widget.
- **Draft-from-the-UI is not bindable.** Epic 10 drafts through `job-hunt.yaml`'s `pack.each`
  over `tailor.yaml`, which needs the posting text, its url and an `out_dir` per subject. No
  closed binding source produces a join of two values or reaches the posting from the review
  screen. The Draft button and the four PDF `file` widgets were left out rather than widening
  the binding language (`e0b079c` adds Declare sent, Skip and Promote only).

## Findings about the seam and the spec

1. **Progress is per step (Epic 12 finding 1, still true).** `judge.each` over a whole board is
   one `Step` started and one done. Nested runs are worse: `pack.each` children report through
   the composition root's runner, so in `-serve` their progress goes to the server's stderr,
   not the browser. Per-run `WithProgress` does not propagate into nested runs. Both need a
   progress channel the core does not have.
2. **The lock excludes the CLI (Epic 12 finding 2, still true).** `-serve` holds
   `.atlas.lock` for its life. The startup line says so.
3. **A late ask can land on the next run.** The asker routes an ask to whichever run holds the
   slot. An agent tool call started by a run that was then cancelled can call `Decide` after the
   next run has taken the slot, and the ask appears on the wrong run's stream. The person sees a
   plausible ask under the wrong screen. Closing it needs a run identity in
   `ports.PermissionRequest`, which is a core change and was not made.
4. **The view schema has no per-row action.** An action binds `state.` by a fixed path, so
   Approve, Override, Skip and Promote act on `rows.0` or `candidates.0`. `open` is the only way to
   pick a row, and it navigates rather than acts. On the review screen that is harmless, because
   the screen is one subject and row 0 is its newest judgement. On the suggestions screen a
   second candidate cannot be promoted.
5. **The spec's `TestNoResponseCarriesTheAPIKey` was never planned or built.** The key is held
   out structurally: `web` never receives config, and the egress table carries scheme and host
   only. The sentinel scan the spec named does not exist.
6. **What the review screen shows differs from 13.3.** It shows the judged subject text
   (`doc.doc.subject`), the verdict, reasons and tripped rules. It does not show the feed
   record of the posting, and it shows no drafted package (finding for Draft above).
7. **The seam was otherwise sufficient.** The asker, the egress table and the loader all plug in
   at the composition root; `judge.assess`, `index.find` and `docs.get` are outbound tools. That
   is a second independent confirmation of Epic 12's story 12.6.

## What surprised me

- **The isolation rule rejected generated code.** Nobody writes `uiv1connect`; the generator
  does, and its default layout is a subpackage importing its parent. The architecture test
  caught it on the first `go test`. The fix was a generator option, not a test exemption.
- **`buf lint` shaped the contract.** `RPC_REQUEST_RESPONSE_UNIQUE` renamed the streamed
  message from `RunEvent` to `RunResponse`.
- **A strict CSP forbids inline style attributes, not just inline `<style>` blocks.** The
  calibration bars could not use `style="width:…"`. They are CSS classes in 5% steps.
- **The vocabulary scan caught a doc comment.** The first draft of `server.go` explained the
  threat model with the words it protects against leaking. It now says "a real person's record".
- **`limit` without ORDER BY is a lie that tests pass.** Every test had one judgement per
  subject. The second judgement was what exposed it, in a hand run.
- **Constructors with side effects.** `termprompt.New` starts a goroutine reading stdin. Moving
  its construction out of the agent branch made every plain pack run drain piped stdin
  (`98a3db4` put it back, pinned structurally).
- **The review screen could not be built from stored data alone.** The judgement record holds
  answers and rules; the reasons a person reads are derived. A UI that "just shows the record"
  would have shown the wrong thing.

## What I would do differently

- Write the spec's named tests into the plan by name, and tick them off at the end. The API-key
  sentinel test fell out between spec and plan and nobody noticed until this note.
- Check each view binding against the pack's real output shape before writing the view file.
  Task 13 found that reasons are not stored and that columns need dotted paths only when it
  first ran the screens.
- Decide the per-row action question before shipping a view that has lists with actions. Row 0
  was fine for review, and quietly wrong for suggestions.
- Put a run id on the asker's routing from the start. The web adapter already knows which run
  it is serving; the port does not carry it, and the gap was found by reasoning, not by a test.

## Known limits and residual risks

Security, open at the close of the build and for the final review to triage:

- **The session cookie is scoped by host, not port.** Any listener on another loopback port that
  the user's browser visits receives `atlas_session`, and its value is the startup token. That is
  inherent to the spec's cookie design. The alternatives are a header token held by the page, or
  a `Secure`/`__Host-` cookie, which needs TLS.
- **`/session` decodes an unbounded body.** It needs `http.MaxBytesReader`.
- **`web.New` accepts an empty token,** and `ConstantTimeCompare("", "")` authenticates. The
  composition root always passes `NewToken()`, which is never empty; `New` should still fail
  closed.
- **An unparseable `Model.BaseURL` reaches the egress table raw.** When `url.Parse` fails,
  `modelEndpoint` uses the whole string, which then reaches `Views`, `NeedsAcknowledgement`, the
  acknowledgement record and a commit message. A base URL carrying credentials would leak them
  there. It should become a fixed placeholder, hosted.

Behaviour:

- **Per-step progress only,** and nested `pack.each` progress on stderr (finding 1).
- **The CLI is locked out while `-serve` runs** (finding 2).
- **A late ask can land on the next run** (finding 3).
- **Actions bind row 0 only** (finding 4).
- **Draft from the UI is not bindable,** so there is no Draft button and no PDF downloads on the
  review screen.
- **`pack.each` child packs are not checked against the view files.** They load by path when the
  parent runs. View authors are pack authors and trusted; the consent gate still holds, because
  it is per server.
- **The job-hunt view's `discloses` list is a declared superset.** None of that view's packs
  calls a model tool today; the list states what the pack family may send, not what a given run
  sends.
- **A tool that ignores its context holds the run slot for good.** The run timeout cancels the
  context; it cannot stop a tool that does not look.
- **The asker holds its mutex across `stream.Send`.** A connected but stuck client blocks
  `Answer`, other asks and release.
- **Any `kind: egress` row with a matching endpoint counts as consent,** including one a CLI pack
  wrote.
- **`Queued.ahead` can be one low,** because internal reads hold the slot without counting.
- **The state cache has no bound** (one entry per view, screen and params seen).
- **The queue lists every judgement,** not one per subject, and cannot be filtered by verdict
  from the UI. A subject with no judgement shows a template error from `review.yaml`.
- **CI checks the bundle, not the generated code.** Drift between `ui.proto` and the committed
  Go or TypeScript is not caught, and a new untracked asset that leaves `index.html` unchanged
  passes the `git diff` check.

**The browser check is pending for the owner.** Every path was driven against the built binary
over Connect: unary calls with curl, streaming `Run` with a small stdlib helper that frames
Connect's envelopes. Screens, actions, the gate, consent, the refusal of an off-list input and
Ctrl-C with a run in flight were exercised that way and by the `TestServe*` tests. No person has
yet opened the UI in a browser, watched a screen render, clicked an action and seen the result.

## What I still do not understand

- Whether a per-row action can be added without the binding sources growing into a small
  expression language. A `row.` source bound to the clicked row looks enough, but it needs the
  row's identity to survive the round trip without trusting the browser, and the state cache is
  keyed by screen, not by row.
- How the app behaves in a real browser under the CSP, the Svelte 5 effects used as mount hooks,
  and a hash change while a run is streaming. The RPC contract is tested; the rendering is not.
- Whether the cookie-by-host risk matters in practice on a laptop that runs other local dev
  servers, or whether a header token is worth the change to every RPC call.
- How an agent's ask should be routed when its run is gone: deny at once, or keep it for its
  run's identity. Both need the run id the port does not carry.

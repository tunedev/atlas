# Epic 10: the apply loop, and a policy that says no

## What the pattern was

**Decide in code, act by stage, never submit.** `judge.each` scores a board, `policy.decide`
turns each scored row into allow, deny or ask with a fixed precedence (a tripped deal-breaker
denies, a deny rule beats an allow rule, an unknown deal-breaker caps at ask, an allow rule
allows, anything else asks), `stage.attach` adds each row's current stage, and two `pack.each`
steps run `skip.yaml` over `decision=deny,stage=` and then `tailor.yaml` over
`decision=allow,stage=`. Skips run first, so a draft that fails cannot hold a skip back. The
stage is the idempotency key: a posting with any stage is never drafted or skipped again, and
`pack.each` re-reads the stage just before each child, so a duplicate row cannot redraft.

**The user declares what the platform cannot see.** A stage is a free string with a time and who
declared it. `stage.declare` enforces only what holds for any timeline: not in the future, not
before the current stage, and the same stage twice is a no-op. `sent.yaml` is how the user says
"I sent it", and `sent_at` is the clock Epic 11 reads.

**Rules are promoted, never inferred.** `policy.suggest` reads the decision log and prints a
candidate rule with its evidence. It writes nothing; `policy-promote.yaml` appends a rule only
when the user runs it.

**The refusal is enforced.** `http.request` refuses every method but GET and HEAD, and
`internal/arch/submit_test.go` fails on any write method in any module package the tools package
depends on (`go list -deps`), except the model endpoint `openaiprov`. It follows imports, not
injection: an adapter handed to a tool through a port at the composition root, such as
`feedsource`, is outside the scan.

**Nothing unverified is declared drafted.** `cv.pdf` and `letter.pdf` render only kept content,
and `render.run` checks every kept string is printed. When nothing is kept for one of them, the
pack's `expect` names a sentence the document cannot contain, so the render fails, the file is
not written, the child errors and the row keeps no stage. The next run tries it again.

## The live run

Everything below ran against a fabricated record and a fabricated board, in a throwaway store,
on `qwen2.5-coder:7b` (Ollama) with Typst 0.15.1. No real CV was read.

### Setup

- **Record.** A made-up lighthouse operations lead, Orla Penhallow: two made-up employers and
  seven bullets, compiled with `typst` and ingested with `packs/profile-ingest.yaml`.
- **Deal-breakers.** One comparable rule, `salary-floor`: `compensation.min >= 40000`.
- **Policy.** `packs/profile/policy.example.json` as written: allow `verdict == apply` and
  `p >= 0.7`; deny `answers.focus == frontend`.
- **Feed.** A local git repo, `postings/greenhouse/skerry/{201..205}.json`:

  | Id | Role | `compensation.min` | Designed to |
  |---|---|---|---|
  | 201 | Lighthouse Operations Lead | 52000 | fit, three of four requirements in the record |
  | 202 | Fog Signal Technician | 31000 | trip the salary floor |
  | 203-205 | Pastry Chef, Orchard Pruner, Violin Repairer | none | leave the salary floor unknown |

  Five postings, not three, so that three hand skips on one verdict could feed `policy.suggest`.

```bash
export ATLAS_STORE_ROOT=$S/store ATLAS_STORE_INDEX_PATH=$S/index.db \
  ATLAS_STORE_HISTORY_PATH=$S/history.duckdb ATLAS_FEED_REMOTE_URL=$S/feed \
  ATLAS_FEED_CACHE_PATH=$S/feed-cache ATLAS_MODEL_NAME=qwen2.5-coder:7b \
  ATLAS_RENDER_TYPST=typst
atlas -pack packs/profile-ingest.yaml -var cv_path=$S/cv.pdf
atlas -pack packs/record-commit.yaml -var source=$S/input/dealbreakers.json \
  -var path=profile/dealbreakers.json -var kind=profile -var fields='section: dealbreakers' \
  -var expect=json -var message="Add the dealbreakers"      # and the same for policy.json
atlas -pack packs/job-hunt.yaml -var board=skerry \
  -var rules=profile/dealbreakers.json -var policy=profile/policy.json \
  -var store_root=$S/store -var out_dir=$S/out -var profile="Coastal operations: ..."
```

The fit was judged `apply` at p=0.686, under the policy's 0.7, so it was asked, not drafted. That
is the policy doing its job. The user lowered the allow threshold to 0.6 and committed the policy
again through `record-commit.yaml` ("Allow a strong fit from p 0.6").

### Run 2: the allowed one drafted (10.5 s)

```
201 reused=true decision=allow matched=[strong-fit] because="allowed by: strong-fit" stage=""
202 reused=true decision=deny  because="tripped: salary-floor"                      stage=not_applied
203-205 reused=true decision=ask because="unknown: salary-floor"                    stage=""
draft: count=1 ok=1 (201)   skip: count=0
```

Every judgement was reused: the policy is not part of a judgement's fingerprint, so changing it
re-decides without re-asking the model. 202 was not skipped again because it already had a stage.

## The empty letter: engine state, not the pack

`letter.pdf` in run 2 was empty, and `tailored.json` shows `"letter": {"sentences": []}` with no
letter gaps, so the model returned an empty list rather than sentences the checks removed.

**Measured.** `tailor.yaml` was re-run by hand for the same posting, in a copy of the store,
behind a logging proxy. That run's letter request returned two sentences (516 completion tokens).
Replaying the identical captured request body straight to Ollama:

| Condition | Completion tokens per call | Letter sentences |
|---|---|---|
| model warm, replayed alone | 8, 8, 8, 8, 8 | 0 |
| model warm, after the bullets request | 8, 8, 8 | 0 |
| model unloaded first (`keep_alive: 0`), first call | 507, 507 | 2 |
| the call right after that | 8, 8 | 0 |

The same bytes at temperature 0 give a letter on a freshly loaded model and `{"letter":[],
"answered":[]}` once it is warm. Nothing in Atlas differs between the two, and the letter step is
unchanged by this epic. The live run's letter request came after five judge calls, on a warm model.

**What the pack does with it.** An empty letter is a failed draft: `letter_pdf` renders with an
`expect` no page can satisfy, so no `letter.pdf` is written and `drafted` is not declared. The
same guard covers a CV with no kept bullet. Whether the model writes a letter on the next run is
still the engine state above.

**CUDA error.** The first attempt at the proxied run failed with Ollama returning 500:
`CUDA error: an illegal memory access was encountered`, `llama runner terminated`. The retry ran
cleanly. That restart is what made the proxied letter request land on a fresh model.

## Follow-ups outside this epic

- **Epic 9: a kept sentence can state a listed gap.** The two-sentence letter from the cold call
  printed "Additionally, I have a certificate in marine diesel engineering", citing the generator
  span, which the judge passed as relevant (p=0.886). The same requirement is the review sheet's
  only gap. `render.run` checks gap text only outside kept content, so a kept sentence may state
  a listed gap.
- **Epic 9: span markers are printed.** The model wrote "(span [2])" into its sentences, and they
  reached the letter.
- **Epic 6: CV end dates.** The CV headings print "2020" and "2015" with no end: ingest left the
  first entry without `ongoing` and both without `end`, and the CV prints "present" only when an
  entry is marked ongoing.

## The contract Epic 11 reads

| Field | Where | Meaning |
|---|---|---|
| `stage` | index, kind `stage`, path `applications/<subject_id>/stage.json` | The current stage, a pack-defined string |
| `<stage>_at` | same row | RFC 3339 time each stage was last reached; `sent_at` is the clock |
| `declared_by` | the document | Who declared the current stage (`user` or the pack's name) |

Re-declaring a stage the subject left earlier moves its `<stage>_at` to the new time; git keeps
the earlier one.

## Rulings made during execution

- **Plan R1-R8.** No `apply.yaml`: `tailor.yaml` is the one-action package pack and ends with
  `stage.declare drafted`. `judge.each` rows carry `item`, `answers` and `source_id`, so
  `pack.each` needs no second fetch. `pack.each` returns vars and ok or error, not the child's
  state. `policy.suggest` groups by verdict alone. The policy is a record path read through
  `ports.Docs`. `stage.declare` finds an existing stage with `Docs.List`. All children failing
  fails the step.
- **T1:** the architecture test also catches `http.Post`, `PostForm` and friends and
  case-insensitive quoted write methods, and the pattern is pinned by its own table test.
- **T3:** `app.Decision` became `app.PolicyDecision` (it collided with the recorded choice). A
  deny rule that cannot be evaluated caps at ask, never lets an allow through. Conditions are
  evaluated order-independently; `{"rules": null}` and unknown top-level keys are rejected.
- **T4:** `<stage>_at` is the last time reached. Stage names match `^[a-z][a-z0-9_]*$`.
- **T5:** `pack.each` formats floats in matches and id sorts the same way, trims fields and
  values, checks `ctx.Err()` per row, and counts `skipped`.
- **T6:** suggestions are grouped by (verdict, mapped decision) through a `choices` map the pack
  supplies; each subject counts once, by its latest decision; contradictory candidates are both
  shown. `job-hunt.yaml`'s automatic skips are recorded as `policy_skip`, outside `choices`, so
  they never become evidence (shown live above). `choices` is written as a block scalar, because
  a YAML flow map does not load into a string var.
- **T7:** the agent is started with the registry from before `pack.each` is added, so a pack the
  agent writes cannot run tools outside its allowlist; the child registry also lacks `agent.do`.
- **T8:** a long url wrapped in `instructions.pdf`, grounding saw a space, and the child failed and
  re-ran the model pipeline every time. The template keeps a link on one line and scales an
  over-wide one. `job-hunt.yaml` quotes path vars with `json`.
- **Final review:** `job-hunt.yaml` skips before it drafts. `tailor.yaml` fails the render of
  a CV or letter with nothing kept. The refusal's architecture test scans every module package
  the tools reach, and its call branch matches only `Post` and `PostForm`, the write helpers
  `net/http` has, so a store's `Put` is not mistaken for one. Child packs print their progress
  indented under the parent step, prefixed with the child's pack path.
- **T9:** five postings instead of three, so that suggestion evidence could be real; the policy's
  0.7 threshold was lowered to 0.6 by the user after run 1, as a committed policy change.

## What surprised me

- **The first real decision was "ask".** The fit scored 0.686 against 0.7, and the loop drafted
  nothing. Changing the policy re-decided in seconds from reused judgements. A policy is cheap to
  tune because the model is not in its loop.
- **The loop's guarantees held; the tailoring under it did not.** Stages, idempotency, the send
  clock, the refusal and the suggestion all behaved exactly as specified, while the drafted
  package had an empty letter. A `drafted` stage says each sendable document has at least one
  verified statement in it, not that the package is worth sending.
- **Engine state changes answers at temperature 0.** Epic 9 saw spread between identical requests.
  Here it splits cleanly on whether the model was just loaded.

## What I would do differently

- Run the live check with the logging proxy from the start, as Epic 9 advised. The live run's own
  letter request was not captured; the evidence comes from a re-run.
- Count each extraction step's items in the pack's output, so an empty letter shows up as a
  number in the run, not as a blank page found afterwards.
- **The loop's remaining limit.** When every draft in a run fails, `pack.each` fails its step
  (R8), the run stops, and the ask list is not printed. The skips have already run. The asked
  rows are not lost: their judgements are in the index and the policy re-decides them on the next
  run, but until a draft succeeds or the failing row is skipped by hand, no run prints them. A
  run that reports failed children and still prints the ask list would need `pack.each` to
  succeed with error rows, which R8 chose against.

## What I still do not understand

- Why a freshly loaded qwen2.5-coder:7b writes the letter and a warm one returns an empty list
  for the same bytes. Prompt-cache reuse in Ollama is the obvious suspect, but the replay after an
  unrelated request was also empty, so it is not only reuse of this prompt's prefix.
- Whether the judge's p for a borderline fit is stable enough for a policy threshold. 0.686 against
  0.7 was decided by 0.014, and one run is not a spread.

## Deliberately not built

As the spec's table: submitting anything, inferring rules silently, a UI for asked postings,
reminders from the clock, editing a declared stage other than by declaring a later one, and
parallel drafting. Also not done here: checking that kept sentences do not state a listed gap
(Epic 9, above).
